# 真实验收

这是发布前的人工作业单；不要为了生成测试报告而擅自执行真实危险操作或批准任何请求。

## 记录环境

记录 Windows 版本、Python 版本、Codex 扩展版本、`codex --version`、本地/WSL/远程模式、是否自定义 CODEX_HOME。公开报告使用占位符替换用户名与私有路径。

## 操作顺序

1. 安装后在 `/hooks` 查看本工具三个条目的命令、启用与信任状态；重载 VS Code。
2. 通过 Test Codex Alerts 打开测试窗。切换到其他应用，确认仍可看见，静音时也可使用。关闭后用 `--status` 确认后台还在运行。
3. 在已有 A 对话发起一个无副作用的小任务，等待本轮结束，确认显示项目和会话标识。
4. 在已有 B 对话重复；再新建 C 对话重复。不要在 A 中重新写通知提示来辅助 B/C。
5. 恢复较早日期的对话，重复一次，验证不是只扫描当天文件。
6. 在支持结构化提问的场景请求一个必须由用户选择的问题，确认中途提问能提醒。记录具体工具路径；自然语言提问可能只在本轮结束时提醒。
7. 在隔离测试项目里触发一个无副作用、按当前审批策略确实需要确认的操作。确认提醒后，到 Codex 自己的审批界面决定；本工具不得替你作决定。不为测试放宽审批策略。
8. 同时运行 A/B，确认两条提醒均入队；相同结束事件不能因 Hook + 文件通路变成两条。
9. 保留一条未读提醒，关闭并重新启动提醒后台，确认仍显示。然后全部已读，再次启动不回放它。
10. 执行 `--stop`，确认同一次登录内 Hook 不把程序拉起；桌面入口可恢复。登录启动与实际注销/登录单独测试。
11. 在隔离 CODEX_HOME 中预置其他 Hook，重复安装两次并停用，确认其他处理器和组元数据仍保留。
