# 排错和迁移

## 测试窗口不出现

先在正确的 Windows 用户下运行已安装的 `alerts.py --status`。`running=false` 表示没有最近心跳；通过桌面入口或 `pythonw.exe alerts.py --daemon` 启动，检查安装目录的 `errors.log`。不要仅凭 status.json 文件存在就判断正常，它可能是旧文件。

`running=true` 但看不到窗口时，执行 `--test`，检查 `pending_alerts` 和 `window_visible`。查看任务栏、多显示器布局、全屏程序遮挡。`disabled` 表示已停用，请重新安装；`paused` 可由桌面入口恢复。Tkinter 缺失则需要安装包含 Tcl/Tk 的 Python。

## 完成能提醒，审批/提问不能

1. 检查 `/hooks`，确保三个条目来自当前选定的用户级目录，命令指向正确安装目录，已启用且受信任。
2. 重载 VS Code。CLI 和 IDE 可能使用不同 CODEX_HOME 或不同主机。
3. 检查自己是否在 WSL、远程 SSH 或云端模式。本版本只支持相同 Windows 主机上的本地数据。
4. 确认真有审批事件：无需审批的命令不会触发 PermissionRequest。不能为了测试而降低安全策略。
5. 提问工具名可能变化，也可能未经过受支持的本地工具 Hook。提交经过脱敏的工具名和版本；不要提交整份会话正文。

补充监听文件格式变化后可能不再识别。`read_errors` 是文件读错误计数，`watcher_error` 是最近循环异常类型；二者为零也不证明新版格式仍然兼容。

## 没有 /hooks 或版本不兼容

按照 OpenAI 官方文档检查当前版本是否支持 Hooks。不要把 slash 命令写成让模型执行的自然语言提示，也不要修改信任数据库或使用绕过参数。若没有支持的审阅入口，暂不要依赖审批/提问提醒。

## 旧个人原型迁移

第一版本地脚本可能只有 alerts.py、使用说明和中文桌面快捷方式，没有 manifest.json。正式整理版可在同一个默认安装目录覆盖程序，并识别具有旧 `Codex desktop alert` 标记、且命令精确指向该安装目录的 Hook。需要重新审阅信任。

早期中文桌面入口不在新安装清单内，停用脚本不会自动清理它们；可自行删除这些旧快捷方式。旧 notify 不参与本工具，但也不会自动删掉，因为它可能服务于其他功能。

本次工程整理不会自动替换电脑上正在运行的原型。请先审阅源码与安装计划，再决定是否升级。

## 安装失败或要恢复

解析失败的 hooks.json 不会被强行覆盖。先修复文件后重试。安装会先暂停旧实例；若中途出现文件权限或快捷方式冲突，可能留下已复制文件/Hook，安装不是覆盖所有系统操作的事务。检查输出、运行已安装的停用脚本，或排除冲突后重新安装。

备份位于安装目录 backups。恢复前先比较当前配置，避免把安装后新增的其他 Hook 覆盖掉。不要将整份备份上传到 Issue。

若升级 Python 后原解释器路径失效，使用新解释器重新运行安装器。若停用脚本因此无法启动，使用新 Python 直接运行 `manage.py uninstall --install-dir '<安装目录>'` 清理 Hook，再手动删除本工具快捷方式。
